## 3. Architecture results

### Architecture A
Flow: homepage login form → fill username (seeded "john") → fill password
(seeded "demo") → click Log In → **`overview.htm` (ACCOUNTS OVERVIEW —
authenticated)** → About Us ↔ Services navigation. Termination: `completed`.

NOTE: mid-run the model emitted two NEW malformed-response classes
(unescaped attribute-selector quotes, inline ```html fences). The new
tolerant parser landed DURING this session; this run pre-dates full
protection for the quote case — deterministic fallback carried those steps
with the CORRECT seeded values anyway (the fallback also reads SEED_*).

Tests: TC001 valid login (grounded in real recorded flow!), TC002–TC005
post-login navigation flows.

### Architecture B
10 steps across index → services (session-id URL) → register page. OCR read
login labels; filled seeded username on several states. Anti-laziness floor
did not need to fire (no early done). Replay workflow PASSED live (1/1).

### A/B comparison
Zero common elements again (selectors vs visual labels). A contributed all
executable structure incl. the money flow (login); B contributed 231 of 239
catalog elements — the vision-dominance extreme of the campaign so far.

from the free model pool mid-run. Existing retry logic absorbed them;
deterministic fallback covered the rest. No action needed beyond monitoring.

## 6. Where the project lagged

- Element identity space: 231 of 239 elements are vision-only with no DOM
  selector → Fusion can never execute them under the current executor
  (coordinate execution remains the top V2 item).
- A explored breadth-first nav links instead of diving into banking forms
  (transfer/bill-pay) — goal-driven frontier (#4 backlog) would help here.
- B burned several fills re-entering "john" into already-filled fields
  (per-state tried-keys don't carry across identical-looking inputs).
